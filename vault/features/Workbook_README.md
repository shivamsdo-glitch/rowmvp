# README

ROW Module – Consolidated Feature Union

| Primary focus | The 'ROW Features' sheet is the deliverable: features for Right-of-Way (ROW) land acquisition, relocation, condemnation, payments, property management, utilities coordination, and the platform capabilities ROW needs (documents, workflow, GIS, reporting, security, integration). It is built only from the six ROW/real-estate requirement documents (NH DOT, Idaho, NMDOT, WSDOT, Austin, Osceola §6.1.7). |
| City / County sheet | 'City-County ROW Use' is a SEPARATE sheet. It holds requirements for managing USE of public right-of-way (permits, inspections, street/curb data) from city/county-level documents (Detroit, Calgary, Regina, Smart ROW matrix). These are city/county level requirements and are NOT part of the ROW module scope above; they are kept only for reference. |
| Sheets | ROW Features – the union for the ROW module.  City-County ROW Use – separate, reference only.  Traceability – every source item behind every feature (verbatim).  Sources – the documents and how priority was read.  Summary – formula counts.  Open Questions – items I could not determine. |
| Consolidated priority (formula) | Computed from the per-source codes, using the HIGHEST rating any counted source gave: Must Have (M) > Should Have (S) > Could Have (C) > Stated – no priority (E) > Aurigo-only. It means 'at least one source requires it', not agreement – use '# sources', '# sources rating Must' and 'Consensus tier' for weight. |
| Per-source codes | M = Must/Required.  S = Should/Desired/Medium/Preferred.  C = Could/Optional/Low.  E = stated as needed but no priority given (typical of RFIs).  Blank = not mentioned. Exact rule per source is on the Sources sheet; the source's own label is kept in 'Source references'. |
| Consensus tier | Tier 1 = rated Must by 3+ sources; Tier 2 = Must in 2; Tier 3 = Must in 1; Tier 4 = Should only; Tier 5 = Could only; Tier 6 = stated, no priority. Useful because NH and Idaho rate almost everything as required. |
| Aurigo coverage columns | Judged ONLY from Aurigo documents in the project (ROW Pro SOW – Original and Pro versions, demo script, deck, library list). 'Covered (SOW)' = named in the SOW; 'Partial' = related but not the full ask; 'Platform / demo only' = in demo script/deck, not SOW; 'Not evidenced' = nothing found in those documents (not the same as 'product lacks it'). |
| 'Also asked by city/county docs' | On ROW Features, this column notes where a city/county document also asks for a similar capability. Those mentions are NOT counted in priority or source counts. |
| De-duplication caveat | Feature count is my consolidation, not a count of source requirements. Similar asks were merged; report-tool minutiae in the Idaho RFP are summarised in a few features. NH rows with truncated text are not mapped (see Open Questions). |
| No-guess policy | Descriptions restate what sources say. Undefined terms are quoted, not interpreted; see Notes and Open Questions. |
| Build roadmap columns | 'ROW Features' columns Z-AC: Release (R01-R35), Release theme, Build sequence (unique 1-323), Depends on. See the 'Release Key' sheet for release themes, rules and assumptions. |
| New requirements (ROW-233 to ROW-323) | 91 process-step requirements added from New_Requirements.md (rows 236-326 of 'ROW Features'). They come from process sources (SOPs, DOT manual sections, lifecycle stages), not from the six RFP/RFI documents, so columns M-R are blank, priority is 'Stated – no priority', consensus tier is Tier 6, and Aurigo coverage is 'Not assessed (new)'. Evidence is in 'Source references' and on the Traceability sheet (rows marked source code NEW). |

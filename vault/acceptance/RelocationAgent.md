# Relocation Agent — acceptance cases

**Who:** the relocation specialist. Interviews displaced owners and tenants and records what they need.
**Sees:** full control of a parcel's Questionnaire tab; read-only on everything else a relocation agent needs, as set out in the access spec.
**Also run:** every case in [Everyone.md](Everyone.md) as this role.

## Jobs possible today

| Id | Job | Steps | Expected: on screen | Expected: server and data | Status | Run by |
|---|---|---|---|---|---|---|
| AT-RA-40 | Keep the relocation questionnaires of a parcel | Open a parcel's Questionnaire tab. Try to add without a relocation type, then pick one, set a due date, add an ownership interest and a question with its answer, add the questionnaire, attach the answers, change the type, remove a question, remove the questionnaire | Each questionnaire gets an ID; the list shows type, dates and number of questions; the attachments panel appears on the edit form | Ten adds at once are numbered one to ten without a gap or repeat; a missing type, an empty name or question and more than 50 rows are refused (400); the grids are replaced as sent | ✅ | E2E `AT-RA-40`; API `QuestionnaireApiTests`; frontend `parcel-tabs.test.tsx`; unit `QuestionnaireTests` |
| AT-RA-41 | Keep a displacee's relocation on a parcel | Open a parcel's Relocation tab. Try to add with nothing filled in, then enter the relocation number, displacee name and type, a GIN delivered before it was mailed, two primary contacts, an eligibility row, a contact log entry and a status note; add, attach the plan, change the target vacate date, remove it | Each relocation is listed by its number with the displacee and type; the required fields and the backwards date are shown as errors; the vested owner name is derived | The relocation number is unique on the parcel (409); a missing number, name or type, a second primary contact, a negative claim limit and more than 50 rows are refused (400); the grids are replaced as sent | ✅ | E2E `AT-RA-41`; API `RelocationApiTests`; frontend `parcel-tabs.test.tsx`; unit `LifecycleTabsTests` |
| AT-RA-42 | A parcel becomes Acquired when every displaced interest has finished relocating | On the Ownership interests tab tick "Displacement required" on two owners and leave a third unticked. On the Relocation tab add a case for the first owner (pick the owner from the list) and set its Relocation complete date: the parcel is not yet Acquired and the tab says "1 of 2 displaced interests relocated". Add and complete the second: the parcel's status becomes Acquired | A relocation must be linked to an ownership interest of that parcel (a foreign interest is 400); a parcel with no displaced interests is never changed by relocations; the status is set only when the agency's "Acquired" status exists (otherwise the tab warns); `GET /parcels/{id}/relocation-progress` reports displaced, completed and ready; an unknown exception, an appeal before the denial or a completion before the vacate date is 400 | ✅ | E2E `AT-RA-42`; API `RelocationWorkflowApiTests`; unit `RelocationCalcTests`; frontend `relocation-workflow.test.tsx` |
| AT-RA-43 | A relocation payment goes through the approval chain and is paid by Finance | On a relocation request a payment (type, typed amount, advance, taxable). It shows its required sign-offs. The Relocation Agent who asked cannot approve it; the Project Manager approves (and Finance too for a larger amount); Finance marks it paid with a reference. A rejection needs a reason | The steps come from the agency's bands for the amount; only the next role in the chain (or Admin) can sign; nobody signs their own request or signs twice; only an approved payment can be marked paid, by someone with update on Payments; an ineligible displacee cannot get a payment; a relocation with an approved or paid payment cannot be removed | ✅ | E2E `AT-RA-43`; API `RelocationWorkflowApiTests`; unit `RelocationCalcTests`; frontend `relocation-workflow.test.tsx` |
| AT-RA-44 | See the approval chain relocation payments follow | Open Configuration (read) or the payment panel: the dollar bands and the roles that sign each, marked as placeholder defaults until an administrator saves their own | `GET /relocation-payment-bands` is 200 for anyone who reads the Relocation tab; only an administrator can `PUT` them (403 otherwise); a band set with a gap, overlap, unknown or repeated role is 400 | ✅ | API `RelocationWorkflowApiTests`; frontend `relocation-workflow.test.tsx` |
